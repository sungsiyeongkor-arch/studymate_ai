## 환각 방지의 실제 한계

[직접 재현한 결과](validation/grounding-limit.json): 원문 `Working memory has limited capacity.`에 대해 `Working memory has unlimited capacity.`라는 반대 의미의 요약과 유효한 source ID를 넣으면 형식·출처 검사는 통과한다. 이는 실제 모델이 해당 답변을 했다는 기록이 아니라, 현재 검사로 의미 모순을 탐지하지 못한다는 반례다.

현재 검증은 JSON 구조와 인용 ID의 존재·버전을 확인한다. 문장별 의미적 뒷받침, 수치·부정 표현·조건의 충실성, 문제 정답의 교육적 타당성까지 증명하지 않는다. 일반 지식 모드는 별도 표시하지만 외부 사실 검증 도구와 연결되어 있지 않다. 원문 자체가 잘못 인식된 경우 그 오류가 생성 결과에 전파될 수도 있다.

검색은 어휘 기반 제한된 후보 검색이므로 긴 강의의 중요한 근거를 놓칠 수 있다. 프롬프트에 문서를 비신뢰 데이터로 취급하도록 지시하지만, 실제 모델에 대한 프롬프트 주입 공격 저항성을 실측하지 않았다. 이전에 저장한 대화의 원문 링크는 최신 자료로 이동하므로 표시된 인용 버전과 수정 이력을 함께 확인해야 한다.

JSON mode는 유효한 JSON을 목표로 하며 스키마나 진실성을 보장하지 않는다. Structured Outputs를 도입해도 의미 오류가 없어지는 것은 아니다. [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs). 설정된 모델 이름은 [공식 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-astra)에서 확인했으나 계정별 사용 권한과 실제 호출 성공은 확인하지 않았다.

## DB와 운영 범위

로컬 앱 DB를 읽기 전용으로 검사했다. 19개 앱 테이블, 마이그레이션 f08629bd1148, SQLite integrity_check=ok, 외래 키 위반 0. 스키마 drift 검사와 pip check도 통과했다. 이는 데이터의 내용이 사실이라는 뜻이 아니다.

100만 행 데이터는 합성 부하 시험 데이터다. 실제 사용자가 축적한 운영 데이터나 검증된 지식 데이터베이스로 표시하면 안 된다. 기존 성능 수치는 로컬 단일 프로세스·warm-cache SELECT 결과이며 운영 동시 사용자 수의 보장이 아니다. 공개 배포, 다중 서버 장애 전환, 운영 환경의 장시간 부하는 이번 검증 대상이 아니다.

## 실제 AI 검증을 완료하려면

API 키 설정 후 권한이 있는 실제 강의 자료와 사람이 만든 정답을 사용한다. 같은 평가 자료로 아래 항목을 반복 측정하고, 모델명·설정·원문 버전·응답·평가 결과를 보관한다. 기준은 평가 전에 정하고 비교 데이터는 필체 참고 예시와 분리한다.

- 손글씨 OCR: 크기·해상도·수식·한영 혼용별 문자 오류율, 작은 글씨 crop 전후 비교, 예시 참고 유무 비교.
- 받아쓰기: 전문 용어 정확도, 단어/문자 오류율, 무음 구간에 생성한 문장 수, 5분 경계 중복·누락, 2시간 이상 실제 파일의 재개 및 비용.
- 근거 답변: 문장별 근거 충실도, 잘못된 인용, 자료에 답이 없을 때 응답 유보, 상충 자료·부정 문장·숫자·프롬프트 주입 사례.
- 퀴즈: 정답의 유일성, 해설과 원문 일치, 오답 선택지의 타당성. 형식 검사만으로 채점 신뢰성을 판단하지 않는다.

이후 문장별 원문 인용과 별도의 의미 검토 단계를 도입할 수 있으나, 같은 모델의 자기 검토만으로 품질을 인증하지 않는다. 사용자 정정·신고와 사람이 검수한 고정 평가셋을 함께 사용한다.
