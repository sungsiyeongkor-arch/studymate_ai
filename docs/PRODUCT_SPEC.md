# StudyMate AI 세부 기획 · 구현 대응표

작성 기준: 사용자가 제공한 전체 기획 대화와 이 저장소의 실제 개발 버전. 아래의 ‘현재’와 ‘후속’은 구현 여부를 구분하며, 외부 API 품질 검증을 완료했다는 뜻이 아닙니다.

## 1. 해결하려는 문제

학습자료가 필기 앱, PDF/PPT, 녹음 파일, 채팅창에 분산되어 있습니다. 요약만 읽으면 이해했다는 느낌은 생겨도 스스로 설명하고 시험에서 적용하기 어렵습니다. 작은 손글씨·전문용어의 인식 오류가 요약과 문제의 오류로 전파될 수 있습니다. 긴 녹음은 업로드·처리가 중단되면 시간과 비용을 다시 지불해야 합니다.

StudyMate는 **자료 수집 → 인식 검수 → 개념 이해 → 인출 연습 → 복습 기록**을 연결합니다. ‘AI가 정답을 확정한다’는 흐름 대신 근거와 수정 경로를 사용자에게 제공합니다.

초기 타깃은 전공 수업을 듣는 대학생·자격시험 학습자입니다. 과목과 강의를 중심으로 구성하고, 전문용어가 많은 강의와 Goodnotes PDF를 주요 사용 사례로 삼습니다.

## 2. 제품 경계

자체 필기 앱은 만들지 않습니다. Goodnotes 등의 PDF 내보내기를 입력으로 받아 원문 열기·영역 선택·텍스트 교정을 제공합니다. 굿노트의 펜/페이지 편집·동기화를 대체하지 않습니다.

다글로와 A. 노트는 사용자 요청에 따른 참고 제품입니다. 긴 녹음 처리, 읽기 쉬운 전사, 수정, 요약과 검색이라는 편의 방향을 참고합니다. 특정 기능의 사용자 만족도 순위나 실제 이용 후기를 이 개발에서 조사·검증했다고 주장하지 않습니다. 브랜드·디자인 자산을 복제하지 않습니다.

## 3. 핵심 이용 시나리오

### 강의 전

과목을 만들고 강의 제목·단원·소주제·언어를 입력합니다. PDF/PPTX를 업로드하고 추출 상태를 확인합니다. 전문용어를 직접 등록하거나 자료에서 추출한 후보를 확인합니다. 강의자료 업로드는 모델 훈련이 아니라 **해당 강의의 검색 가능한 원문과 참고 힌트를 만드는 과정**입니다.

### 강의 중과 직후

기기의 녹음 앱으로 수 시간 강의를 저장해 올리거나 브라우저에서 짧게 녹음합니다. 업로드는 조각별 상태를 저장하고, 작업자는 분할된 음성을 처리합니다. 전사 시간 버튼으로 원음을 재생하면서 오인식 부분을 고칩니다.

### 필기 자료 확인

작은 글씨가 있는 PDF 페이지에서 해당 영역을 드래그합니다. 화면 캡처를 확대하는 대신 원본 PDF의 그 영역을 다시 렌더링합니다. 벡터 선과 글자는 원본의 해상도를 활용할 수 있지만 이미 저해상도 이미지로 굳어진 글씨의 정보를 복원하지는 못합니다.

판독 응답은 `visual_text`, `contextual_suggestion`, `uncertain_spans`, `explanation`으로 구분합니다. 원문 읽기와 학습 내용 편집은 다른 수정 이유로 저장합니다. 확인된 본인의 손글씨만 개인 예시로 사용할 수 있습니다.

### 학습과 복습

요약·핵심 포인트를 보고 개념의 관계와 성립 조건을 확인합니다. 원문 영역에서 바로 질문하거나 자료 근거 모드의 챗봇을 사용합니다. 카드는 정답 공개 전에 직접 답하고, 확신도와 난이도를 기록합니다. 틀린 내용은 원문으로 돌아가 확인하고 다시 복습합니다.

초기 기획의 ‘최종 점수’는 현재 버전에서 **자기 평가 기반 인출 기록**으로 구현했습니다. 객관식 자동 점수와 서술형 모델 채점은 미구현입니다. 평가가 개인의 능력 측정 점수로 오해되지 않도록 표시합니다.

## 5. 학습과학 관점의 설계

아래는 기능의 설계 의도와 검증 계획입니다. StudyMate의 학습 효과가 검증되었다는 주장은 아닙니다.

| 설계 의도 | 현재 기능 | 추가 검증·확장 |
|---|---|---|
| 인출 연습 | 정답 공개 전 자유 응답 | 지연 회상 평가, 단순 답 베끼기와 구분 |
| 분산 복습 | 평가에 따른 시간 간격 | 데이터가 충분할 때 개인별 스케줄러와 기준선 비교 |
| 자기설명 | 개념 관계 가리기, 조건 설명, 힌트 모드 | 설명 내용 루브릭·오개념 피드백 |
| 스키마 형성 | 개념–명시적 관계–개념, 연결 조건·출처 | 선수 개념 진단, 사용자 개념도 편집·비교 |
| 메타인지 | 정답 공개 전 확신도 | 확신도와 실제 수행의 보정 차트 |
| 오류의 학습 전파 억제 | 원문 확인, 버전, stale 카드 제외 | 문항 품질 평가, 출처의 불확실성 정책 강화 |
| 인지 부담 조절 | 강의 단위 맥락, 단계별 준비·확인·복습 | 쉬운 설명과 심화 설명의 단계 전환 |
| 전이와 변별 | 적용 질문 생성 요청 | 유사 개념 비교, 반례, 다양한 문제의 교차 연습 |

맞춤 망각곡선은 ‘시간이 지나면 정확히 몇 % 잊는다’는 표시로 시작하지 않습니다. 현재는 공개된 규칙으로 간격을 계산하고, 시도 당시 문항·정답·힌트·확신·이전 상태를 기록합니다. 후속 모델은 사용자별 데이터 수가 적을 때 기준선으로 돌아가고, 문항 오류와 무효화된 시도를 제외해야 합니다.

## 6. 손글씨 개인화의 단계

1. 현재: 원본 영역 + 사용자가 확인한 전사 + 해당 버전을 저장하고, 최근 예시 최대 3개를 멀티모달 API 입력에 참고합니다. 동의하지 않으면 저장/참고하지 않습니다.
2. 다음: 글자 크기·필체·기호가 비슷한 예시 검색, OCR 후보 비교, 의미를 바꾸는 문자에 대한 검수 우선순위.
3. 검증 후: 사용자별 데이터 수·다양성이 충분한 경우 모델 적응 또는 별도 인식기 검토. 학습·평가 페이지를 분리하고 같은 필기 조각의 중복 누출을 막습니다.

평가는 문자 오류율만 보지 않고 전문용어 정확도, 수식·부정 표현 오류, 사용자 수정 시간, 문맥 때문에 원문과 달라진 비율을 함께 봅니다. 잘못 확인한 예시는 이후 판독을 악화시킬 수 있으므로 원문 버전 변경 시 예시를 무효화합니다.

## 7. 녹음·자료 참고의 한계와 개선

현재 `whisper-1`은 시간표시를 얻기 위해 선택했습니다. 짧은 프롬프트 한도가 있어 원문 전체가 아닌 주제·용어·관련 자료 일부를 보수적인 길이로 전달합니다. 관련 단어를 실제 발화 대신 강제 삽입하지 않습니다. 이 메커니즘의 효과는 잡음, 발음, 분야에 따라 실제 비교 평가가 필요합니다.

후속으로 긴 문맥을 지원하는 음성 모델과 정렬기를 교체할 수 있습니다. 같은 음성에 대해 기본 인식 / 주제 / 용어장 / 자료 맥락 조건을 비교하고 전문용어 오류율, 누락·추가, 교정 시간, 처리 비용을 기록합니다. 자료와 음성이 충돌하면 자료 내용으로 음성을 조용히 덮어쓰지 않습니다.

## 8. 데이터와 운영

원본 저장소와 DB를 분리합니다. 개인용 개발은 SQLite, 다중 사용자 배포는 PostgreSQL을 기본 확장 경로로 둡니다. 원본·원문 버전·AI 결과·근거·복습 시도는 분리된 엔터티입니다. 파일당 제한과 형식 검증을 적용하며 실제 저장 용량 예약, 악성 파일 검사·할당량, 비용 원자적 예약은 공개 서비스 규모에 맞춰 강화해야 합니다.

계정별 자료 접근은 서버에서 검사합니다. 키와 업로드 파일은 GitHub에 저장하지 않습니다. AI 기능을 요청하면 해당 자료 발췌·이미지·음성이 외부 API로 전달됩니다. 예시 사용 동의와 원본 변경/삭제의 영향을 화면에 표시합니다.

## 9. 단계별 출시 조건

| 단계 | 완료 조건 |
|---|---|
| 로컬 개발판 | 계정·업로드·원문 수정·복습의 실제 DB 동작, 자동 테스트, 화면 검수 |
| 개인 AI 시험 사용 | 본인 API 키, 사용 가능한 모델 확인, 허가된 짧은 PDF/음성으로 실제 호출·출처 검수 |
| 긴 강의 시험 | 2~4시간 실녹음, 경계 누락·중복·시간 정렬·중단 재개·비용 확인 |
| 소규모 비공개 서비스 | HTTPS, 영구 저장소, DB/파일 백업과 복구 연습, 계정 복구, 저장·비용 제한 |
| 공개 서비스 | 운영 정책·사용자 삭제·모니터링·남용 대응·외부 API 품질 평가·부하 검증 |
| 학습 개인화 고도화 | 홀드아웃 학습 데이터, 기준선 비교, 학습 효과 지표와 오류 분석 |

캘린더 동기화·이메일 알림·친구 공유·협업·모바일 앱·자동 스키마 생성의 교육적 정확도 평가·FSRS류 모델 적합은 후속 로드맵입니다. 구현하지 않은 외부 연동을 화면에 작동하는 것처럼 표시하지 않습니다.
