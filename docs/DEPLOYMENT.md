# 설정 · 배포 · 백업

## 사용자가 직접 준비할 항목

OpenAI 계정의 API 키/결제·모델 권한, 호스팅 계정과 결제, 도메인 소유권은 사용자가 준비해야 합니다. 키나 카드 정보를 이 저장소 또는 채팅에 보내지 않습니다. 현재 로컬 실행과 코드 저장은 이 계정 설정 없이 가능합니다.

OpenAI 공식 문서: [API 시작](https://developers.openai.com/api/docs/quickstart), [Responses](https://developers.openai.com/api/docs/guides/text), [음성 전사](https://developers.openai.com/api/docs/guides/speech-to-text), [모델 목록](https://developers.openai.com/api/docs/models). 실제 계정에서 허용된 모델을 확인합니다. 문서의 모델 명칭과 계정별 사용 가능 여부는 다를 수 있습니다.

## API 설정

1. `.env.example`을 `.env`로 복사합니다.
2. 서버 환경에 `OPENAI_API_KEY`를 입력합니다. 웹 브라우저에 키를 저장하는 설정 화면은 의도적으로 제공하지 않습니다.
3. `OPENAI_MODEL`에 이미지 입력과 JSON 출력을 지원하는 Responses 모델을 설정합니다. 현재 예시는 `gpt-6-astra`입니다. 401은 키, 403/404는 권한/모델, 429는 사용량·요청 제한 등을 확인합니다.
4. 시간표시 음성 어댑터는 `TRANSCRIPTION_MODEL=whisper-1`로 사용합니다. 다른 모델명만 넣으면 지원하지 않는다고 알립니다. 모델에 맞는 출력·정렬 어댑터를 먼저 추가해야 합니다.
5. 웹 서버와 작업자를 모두 재시작하고 설정 화면을 확인합니다. ‘설정됨’은 키 문자열의 존재를 뜻하며 실제 호출 성공을 보장하지 않습니다.
6. 짧은 허가된 자료로 요약·판독·받아쓰기를 각각 시험하고 출처·시간·원문 충실도를 직접 확인합니다.

공식 전사 문서의 파일 제한을 피하도록 서버가 5분 모노 WAV로 나눕니다. Whisper의 프롬프트 한도에 맞춰 맥락을 짧게 제한합니다. 이 한계 때문에 사전 자료 전체를 학습했다고 표시하지 않습니다.

API 사용량은 성공한 요청 기록으로 집계합니다. 현재 `AI_DAILY_REQUEST_LIMIT`은 지난 24시간 호출 수를 제한하는 간단한 장치입니다. 동시 요청과 공급자 과금의 강한 비용 상한이 아니므로 공급자 프로젝트의 별도 예산·사용량 설정도 사용합니다. 12시간 파일은 144개 음성 구간이므로 기본 100회 한도에서는 나중에 이어서 재시도하거나 운영자가 한도를 조정해야 합니다.

## Windows 로컬 실행

README의 가상환경·마이그레이션·웹·작업자 절차를 따릅니다. FFmpeg의 공식 [다운로드 안내](https://ffmpeg.org/download.html)에서 운영체제에 맞는 빌드를 설치한 뒤 아래 명령이 모두 성공하는지 확인하세요.

```powershell
ffmpeg -version
ffprobe -version
```

PATH 변경 후 터미널과 작업자를 다시 실행합니다. 키 없이도 텍스트 문서 추출과 직접 만든 카드의 복습은 가능합니다. 음성 처리는 설정 대기 상태가 되며 설정 후 ‘이어서 재시도’를 누릅니다.

Windows에서는 `python scripts/install-ffmpeg.py`로 공식 FFmpeg 다운로드 페이지가 안내하는 Gyan 빌드를 프로젝트의 `.tools/ffmpeg/bin`에만 설치할 수도 있습니다. 공급자의 SHA-256 값을 확인한 뒤 실행 파일을 추출하며 시스템 PATH는 변경하지 않습니다. 앱은 재시작할 때 이 경로를 인식합니다. 바이너리는 Git에 포함되지 않습니다.

## Docker Compose

Docker Engine/Compose가 있는 서버 또는 개발 PC에서:

```sh
cp .env.example .env
# .env를 편집: POSTGRES_PASSWORD, SECRET_KEY, OPENAI_API_KEY 등
docker compose up --build -d
docker compose logs --tail=100 web worker migrate
```

초기 마이그레이션이 성공한 뒤 웹과 작업자가 실행됩니다. 웹은 기본 `127.0.0.1:8000`에 바인딩하므로 서버 전체에 바로 공개하지 않습니다. PostgreSQL과 Redis 포트는 외부로 노출하지 않습니다. 웹·작업자가 같은 `files` 볼륨을 사용합니다. 환경변수에 URL을 넣기 때문에 DB 비밀번호에 `@:/#%` 같은 URL 예약 문자를 사용할 경우 인코딩이 필요합니다. 배포 시 영문·숫자의 충분히 긴 임의 값을 사용하는 방법이 간단합니다.

공개 배포에서는 `APP_ENV=production`, 임의 생성한 `SECRET_KEY`, HTTPS 리버스 프록시, 인증서·도메인을 준비합니다. `SESSION_COOKIE_SECURE`가 켜지므로 HTTP에서는 로그인 쿠키가 동작하지 않습니다. 신뢰할 프록시 개수를 정하기 전 임의의 전달 헤더를 신뢰하도록 설정하지 않습니다. 현재는 프록시 뒤 클라이언트 IP가 합쳐져 로그인 제한이 공유될 수 있으므로 배포 구성에 맞춰 검증해야 합니다.

이 저장소의 `legacy/render.yaml`은 이전 단일 웹앱 설정의 보관본입니다. 새 앱의 웹·작업자·공유 파일 저장소 요구사항을 만족하지 않으므로 그대로 사용하지 않습니다. 호스팅 업체를 정한 뒤 영구 디스크 공유 또는 객체 저장소 어댑터를 선택해야 합니다. GitHub Pages만으로 실행할 수 없습니다.

## 백업과 복구

DB만 백업하면 원본 파일이 복구되지 않습니다. `DATA_DIR/files`와 DB를 한 세트로 보관합니다. 일관된 개인용 백업은 웹/작업자를 중지한 동안 생성합니다. `.session-secret` 또는 운영 `SECRET_KEY`는 별도 안전한 저장소에 보관합니다.

- SQLite: 중지한 앱의 `instance/studymate-v2.db`와 `instance/files/`를 함께 복사합니다. 실행 중 파일만 단순 복사하지 않습니다.
- PostgreSQL: 앱 쓰기를 멈춘 상태에서 `pg_dump`를 실행하고 같은 시점의 파일 볼륨을 백업합니다. 실제 운영에서는 정기 스냅샷/복구 지점을 구성합니다.
- 복구는 별도 빈 환경에서 먼저 수행하고, 마이그레이션 버전·원본 해시·전사 수정 이력·출처 링크·예정 복습을 확인합니다.

원본 삭제는 해당 파일·전사·개인 필체 예시를 지우고 관련 노트를 재확인 상태로 바꿉니다. 기존 노트와 채팅은 별도로 남습니다. 백업의 보관/삭제는 운영자가 별도 관리해야 합니다. 전체 계정 삭제의 셀프서비스 UI는 후속 개발 범위입니다.

## 중단 복구와 운영 제한

작업자를 다시 시작하면 대기 작업과 15분 이상 진행이 없는 실행 작업을 처리합니다. 실패 작업은 오류를 확인하고 재시도합니다. 완료된 음성 구간은 건너뜁니다. 이미 성공한 공급자 요청의 과금은 프로세스 장애 후 재요청 때 중복될 수 있습니다.

업로드 중 네트워크 단절은 같은 파일을 다시 선택해 이어갈 수 있습니다. 대기 업로드는 24시간 만료 시각을 갖습니다. `flask --app app expire-uploads`로 확인하고 `--apply`로 만료 예약과 조각을 반환합니다. 사용자는 설정의 업로드 관리에서 대기 업로드를 취소할 수 있습니다. `assembling` 중단은 자동 만료시키지 않습니다. 운영자가 활성 업로드가 없는지 확인한 뒤 수동 복구해야 합니다. 계정 복구, 강제적인 AI 비용 예약, 객체 저장소와 통합 모니터링은 추가 운영 과제입니다. [데이터베이스 운영 절차](DATABASE_OPERATIONS.md)에 백업·복원·검색 인덱스·연결 예산을 정리했습니다.
