# 직접 검수 체크리스트

실제 API 키가 없을 때도 1~6번을 수행할 수 있습니다. 테스트용 표본만 사용하고 실제 사용자 데이터를 데모 계정에 넣지 않습니다.

1. 계정을 만들고 새로고침·로그아웃·다시 로그인해 저장 상태를 확인합니다. 다른 계정으로 동일 자료 URL에 접근하면 404가 나와야 합니다.
2. 과목·강의를 만들고 주제와 한/영 언어를 입력합니다. TXT·PDF·PPTX를 올리고 작업자를 실행합니다. 추출된 페이지/슬라이드 수와 문서를 비교합니다.
3. PDF에서 작은 글씨 영역을 드래그합니다. 원본 영역 이미지가 맞는지 확인하고 직접 전사를 저장합니다. 두 창에서 같은 버전을 수정하면 나중 저장은 충돌 메시지가 나와야 합니다.
4. 개인화를 켠 뒤 본인의 필기 영역을 확인하고 예시로 저장합니다. 일반 페이지나 내용 자체를 편집한 결과는 예시 저장이 거절되어야 합니다.
5. 강의의 학습 노트 탭에서 수동 카드를 만듭니다. 정답을 가린 채 답하고, 힌트·확신도·평가를 기록합니다. 반복 제출이 평가를 중복 생성하면 안 됩니다.
6. 원본·전사·계정 기록을 다운로드합니다. 원본 삭제 후 조회가 차단되고 관련 노트가 재확인 상태가 되는지 확인합니다.
7. API 키 설정 후 한 페이지 요약, 영역 판독, 근거 질문을 수행합니다. 없는 근거를 인용하지 않는지, 문맥 후보를 원문으로 확정하지 않는지 확인합니다.
8. 명확한 전문용어가 있는 짧은 음성으로 기본/맥락 힌트 조건을 비교합니다. 실제 발화에 없던 용어가 추가되지 않는지 확인합니다.
9. 허가된 2시간 이상의 음성을 올립니다. 5분 경계 주변의 중복·누락과 시간 정렬을 직접 검토합니다. 작업자 중단·재시작 뒤 완료 구간을 건너뛰는지 확인합니다.
10. 생성 노트의 근거 원문을 수정합니다. 기존 노트의 경고와 관련 카드의 복습 제외를 확인합니다.
11. 모바일 화면에서 과목·강의·복습·원문 접근이 가능한지 확인합니다. 키보드로 모달을 열고 닫고 필드를 이동합니다.
12. 공개 운영 전 별도 환경에서 백업 복구, 저장용량 부족, 공급자 401/429/5xx, DB 중단과 파일 손상 상황을 시험합니다.

실제 인식 품질 평가는 기준 정답과 함께 CER/WER, 전문용어 오인식률, 임의 삽입·누락, 교정 시간, API 비용을 기록합니다. 손글씨 적응은 같은 페이지의 예시와 평가 조각이 겹치지 않게 나누고, 효과가 없거나 악화된 결과도 기록합니다.
