# 구조와 데이터 설계

## 구성

```text
Browser ES modules → same-origin Flask API → SQLAlchemy → SQLite / PostgreSQL
                              ↓                        ↑
                       immutable originals      durable jobs
                                                       ↓
                                             separate worker process
                                            ↙          ↓         ↘
                                      PDF/text      FFmpeg       OpenAI
```

`app.py`는 WSGI 진입점입니다. `studymate/__init__.py`는 설정, 인증 경계, 오류 처리, CLI를 조합합니다. `api/{auth,catalog,uploads,sources,learning,reviews,settings}.py`는 기능별 HTTP 경계입니다. `api/common.py`에 검증·소유권 조회 공통 함수를 두었습니다.

`services/documents.py`는 형식 검사, 텍스트 추출, PDF 영역 렌더링을 담당합니다. `provider.py`는 외부 API를 격리합니다. `context.py`는 전문용어와 자료의 참고 맥락을 준비합니다. `retrieval.py`는 현재의 어휘 검색 기준선입니다. `learning.py`는 생성 결과와 출처를 검증합니다. `review.py`는 순수 함수 형태의 복습 스케줄러이며 `jobs.py`가 장기 실행을 담당합니다.

프론트엔드는 빌드 도구가 필요 없는 ES 모듈입니다. `app.js`가 인증·라우팅·과목을, `views/lecture.js`가 강의·자료·원문 확인을, `views/learning.js`가 복습·질문·설정을 담당합니다. 사용자·모델 문자열은 HTML로 실행하지 않고 이스케이프합니다.

## 데이터 계층

| 테이블 집합 | 역할 |
|---|---|
| User / Course / Lecture | 소유자 → 과목 → 강의 맥락 |
| Material / Segment | 원본 저장 키·SHA-256·형식과 페이지/시간/영역·현재 전사 |
| Revision | 전사 원본과 사용자 수정, 원문 수정/내용 편집의 구분 |
| Term | 과목별 용어·발음·뜻·연관어·사용자 확인 |
| Job | 작업 상태, 소유 임대 토큰, 진행도, 완료 구간, 맥락/원문 스냅샷 |
| Artifact / Citation | 노트·개념 관계·문제와 근거 구간의 정확한 버전 |
| Card / ReviewState / Attempt | 카드, 다음 복습, 불변 평가 기록·당시 문항·이전 상태 |
| Chat | 질문과 답변, 근거 구간, 답변 방식 |
| HandwritingExample | 본인 확인·동의한 필체 예시와 원문 버전 |
| Upload / UploadChunk | 중단된 업로드의 조각별 수신 상태 |
| Usage | 실제 성공한 외부 API 요청과 반환 사용량 |

모든 사용자 데이터는 `user_id`를 갖고, 조회·수정·다운로드 시 서버가 소유권을 검사합니다. 원본·DB·키는 저장소에 커밋하지 않습니다. 현재 일반 FK는 소유자 일치까지 DB 차원에서 강제하지 않으므로, 서비스 코드에서 부모 소유자를 반드시 확인해야 합니다. 다중 기관 서비스 확장 시 복합 FK 또는 PostgreSQL RLS를 추가합니다.

## 일관성 규칙

- 원본 파일은 추출·수정 중 바꾸지 않습니다. 전사는 `revision` 비교 후 갱신하며 이전 값을 Revision에 보관합니다.
- 원본 구간 수정 시 해당 구간을 인용한 노트가 stale 상태가 됩니다. 그 노트의 카드는 복습 목록과 예정 개수에서 제외됩니다.
- 생성 결과는 원문 버전을 다시 확인합니다. 원본 수정과 경합할 때 PostgreSQL 행 잠금으로 근거 확인과 저장을 묶습니다.
- 인출 카드 평가는 `(user_id, request_key)` 중복 방지와 `state_version` 비교를 모두 사용합니다. 동일 요청 재전송은 같은 평가를 돌려줍니다.
- 문항 오류 신고는 카드를 보류하고 해당 카드의 기존 평가를 통계에서 무효화합니다. 평가 이력 자체는 보존합니다.

## 비동기 작업

큐는 DB 테이블입니다. 작업자는 compare-and-swap으로 작업을 선점합니다. 15분 동안 진행 갱신이 없는 실행 작업은 새 임대 토큰으로 재선점합니다. 저장 전 토큰을 확인해 예전 작업자의 늦은 결과가 적용되지 않도록 합니다.

문서 추출은 이미 있는 `(material_id, ordinal)`을 건너뛰어 사용자 수정을 덮어쓰지 않습니다. 음성은 완료 구간 목록과 전사를 같은 트랜잭션으로 저장합니다. 노트 생성은 결과·카드·완료 배치 표시를 같은 트랜잭션으로 저장합니다. 외부 API 요청과 DB 저장을 단일 트랜잭션으로 묶을 수 없으므로 **API 응답 뒤 프로세스가 죽으면 같은 구간의 비용이 재발생할 수 있습니다.** 결과 저장의 중복 방지와 과금의 exactly-once 보장은 다릅니다.

시간 기반 구간 분리는 5분 경계 양쪽에 2초를 추가합니다. 출력 구간의 중간 시간이 해당 코어 구간에 속하면 채택합니다. 문장 단위 중복·누락을 완전히 방지한다는 보장은 없으며, 실제 음성 평가 후 VAD 분리와 정렬을 개선해야 합니다.

## 확장 지점과 우선순위

1. `retrieval.py`: pgvector와 BM25 결합, 검색 평가셋, 소스별 인용 정확도 평가. 현재 기능을 벡터 RAG라고 부르지 않습니다.
2. `provider.py`: 모델별 기능 지원 명세, 긴 문맥의 음성 모델·정렬 어댑터, 원문 변경을 분리한 전사 교정 제안.
3. `review.py`: 실제 평가 이력 기반 스케줄러 비교와 보정. 초기 데이터에는 현재의 보수적 규칙을 사용합니다.
4. `storage.py`: 객체 저장소 어댑터와 만료 다운로드 URL. 현재 Docker 웹·작업자는 같은 영구 볼륨을 공유해야 합니다.
5. 작업량이 커지면 전용 큐·여러 워커·세밀한 비용 예약·작업 우선순위를 도입합니다. 현재 Redis는 요청 제한 저장소이며 작업 큐는 아닙니다.
6. 운영 계정·이메일 검증·비밀번호 복구·계정 삭제·감사 로그와 관리자 화면을 제품 운영 수준으로 강화합니다.

원본 전체, 길게 생성한 노트, 모든 데이터에 대한 JSON 내보내기는 작은 개인용 배포를 우선합니다. 대규모 서비스는 목록 페이지네이션과 스트리밍 내보내기, 저장용량 예약, 파일 검사 워커 분리를 추가해야 합니다.
